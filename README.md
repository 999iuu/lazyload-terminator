# ⚡ 懒加载终结者

**LazyLoad Terminator** — 让网页图片一次性全部加载完，不再需要下拉、不再需要刷新。

## 这是什么问题？

打开很多网站看图，会遇到同一个烦人的体验：

> 页面打开是一片空白 → 往下拉，图片一张一张冒出来 → 拉动量太大时还得**刷新一下**才显示

这叫**懒加载（Lazy Loading）**——为了省流量，网站故意等图片快滚到眼前才去下载。
但对读者来说，这变成了一种反复的、毫无必要的等待。

**这个插件一次性终结它。**

## 🧠 它是怎么做到的？

绝大多数网站的懒加载都建立在同一个底层机制上：**IntersectionObserver**
（用来观察元素是否"滚动进了视口"）。

本插件在页面加载的**最早阶段**（`document_start`）把这个 Observer 换掉：

```
原逻辑：  observe(img) → 等待滚动 → isIntersecting=true → 开始下载
新逻辑：  observe(img) → 立刻 isIntersecting=true → 立刻开始下载
```

于是所有图片**同时**开始下载，懒加载直接失效。

> **关键点**：插件**不认识任何网站**。它靠打断的是浏览器的通用机制，而不是逐个网站去适配。
> 这也是它能同时在漫画站、图集站、论坛、瀑布流上生效的原因。

在此之上还有三层兜底：

| 层 | 作用 | 覆盖场景 |
|---|---|---|
| ① IO 拦截 | 让"进入视口"判定立即成立 | 原生 lazy、lazysizes、lozad、各种自研 IO |
| ② 属性提升 | `data-src` / `data-original` / `data-srcset` 等 10 种属性直接转正 | 经典 JS 懒加载库 |
| ③ 动态接管 | MutationObserver 监听运行时插入的图片 | SPA、无限流、虚拟列表 |

另外还会：
- 把 `loading="lazy"` 改成 `loading="eager"`（关闭浏览器原生懒加载）
- 做一次「深度滚动扫描」，骗过纯 `scroll` 事件驱动的加载器
  （用户一旦自己滚动过就自动跳过，不会打断阅读）

## 📦 安装

### Edge / Chrome（推荐，本地安装）

1. 打开 `edge://extensions/`（Chrome 为 `chrome://extensions/`）
2. 右上角开启 **「开发人员模式」**
3. 点 **「加载解压缩的扩展」**（Chrome 为「加载已解压的扩展程序」）
4. 选择本仓库克隆下来的文件夹
5. 完成 ✅

> Edge 会提示「来自未知来源」，点「允许」即可。

### 其它 Chromium 内核浏览器

同样在扩展管理页开启开发者模式后加载。

## 🎛️ 使用

装上即用，**无需任何配置**。

打开含懒加载图片的网页后：
- 顶部出现**紫色进度条**，实时显示加载进度
- 浏览器标签页标题同步显示进度
- 全部加载完毕后进度条自动消失，标题自动还原

点击工具栏图标可打开设置面板：

| 开关 | 作用 |
|---|---|
| **全局启用** | 一键关停所有网站的效果 |
| **本站启用** | 只对当前域名生效 —— 某个网站显示错乱时就关掉它 |
| **立即重新加载本页图片** | 手动再触发一次预加载 |

## ⚠️ 已知限制

- **不处理视频**（`<video>` 的流式加载）
- **不处理 canvas / WebGL 渲染的内容**（地图、某些网页游戏）
- **不绕过权限控制**——需要登录才能看的内容不会因为插件而变得可见
- 极少数用 **WebSocket 私有推流**传输图片的站点不适用
- 对**无限滚动**站点会一次性加载更多内容，可能稍多耗一点流量

如果某个网站显示异常，在设置面板里把「本站启用」关掉即可，**不影响其他网站**。

---

## 🔒 隐私

插件**不收集、不上传任何数据**，全部逻辑在本地浏览器内运行。
唯一的网络请求就是网页本来就要加载的那些图片，没有第三方服务器。
