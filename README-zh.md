# 懒加载终结者（通用版）

**作用**：让网页上的图片一次性全部加载完，不再需要「往下拉」「刷新一下」。

**适用**：几乎所有用懒加载的网站 —— 漫画站、图集站、论坛图片、长图文、瀑布流……

> 完整说明、原理与实测数据见 [README.md](README.md)，这里是快速上手版。

---

## 一、安装（Edge / Chrome 通用，1 分钟）

1. 打开 `edge://extensions/`（Chrome 是 `chrome://extensions/`）
2. 右上角打开「开发人员模式」
3. 点「加载解压缩的扩展」（Chrome 叫「加载已解压的扩展程序」）
4. 选择本仓库克隆下来的文件夹
5. 完成，图标会出现在工具栏

> 如果 Edge 提示「来自未知来源」，点「允许」即可。
> **装完请刷新一次目标网页** —— 脚本只在页面打开那一刻注入。

需要 **Chrome / Edge 111 或更高版本**（`world: "MAIN"` 的最低要求）。

---

## 二、怎么用

装上就自动生效，**不需要任何额外操作**。

打开一个有懒加载图片的网页，顶部会出现一条**紫色进度条**，显示「图片预加载 12/86 (14%)」，
标签页标题也会同步显示进度。全部加载完后进度条自动消失。

点工具栏上的插件图标可以：

- **全局启用 / 关闭** —— 关掉后所有网站都不生效
- **本站启用 / 关闭** —— 只对当前域名生效（某个网站如果显示错乱，就在这里关掉它）
- **立即重新加载本页图片** —— 手动再触发一次
- 底部还有**诊断提示**，用来确认插件是否真的在工作：
  - 🟢 `主世界拦截：已生效 · 已触发 N 个元素` —— 正常
  - 🔴 `主世界拦截：未生效（页面未刷新）` —— 按 F5 刷新
  - 🔴 `主世界拦截：未生效（浏览器版本过低）` —— 需要 111+

## 三、原理（v1.1.0 的关键修复）

绝大多数网站的懒加载都建立在同一件事上：**IntersectionObserver**（观察元素是否进入视口）。

本插件在页面加载的最早阶段（`document_start`）把这个 Observer 换掉：
观察到的元素**立刻被判定为「已进入视口」**，于是所有图片同时开始下载。

**但这里有个致命细节**：扩展的 content script 默认跑在**隔离世界**，
在里面改 `window.IntersectionObserver`，页面自己的 JS 根本看不见 —— 等于没改。

所以拦截器被单独拆成 `inject.js`，并在 manifest 里声明 `"world": "MAIN"`，
注入页面主世界，替换才真正生效。

### 为什么要「错峰触发」

很多站点是**串行加载链**：上一张图 `onload` 之后，才去 `observe` 下一张。
如果一次性把几十个元素全部回调，站点的序号逻辑容易错乱、链直接卡死。
本插件给每个元素的回调加了 6ms 的递增间隔（上限 260ms），
模拟"元素依次滑进视口"的真实节奏。

### 四层兜底

| 层 | 作用 | 覆盖场景 |
|---|---|---|
| ① IO 拦截（主世界） | 让"进入视口"判定立即成立 | 原生 lazy、lazysizes、lozad、自研 IO |
| ② 属性提升 | `data-src` / `data-original` / `data-srcset` 等 13 种属性转正 | 经典 JS 懒加载库 |
| ③ 动态接管 | MutationObserver 监听运行时插入的图片 | SPA、无限流、虚拟列表 |
| ④ 失败重试 | 加载失败的图自动重试（最多 3 次） | 串行链中间断掉的站点 |

此外还有**加载看护循环**：前 30 秒每 600ms 扫一遍，之后降到 2.5 秒低频值守，
只要还有图没加载完就会持续补。

因此它**不认识任何网站**，靠的是「打断通用机制」而不是「适配具体网站」。

## 四、实测数据（v1.1.0）

### 串行懒加载链（12 张图，headless Edge 实测）

| | 无插件 | 装插件 |
|---|---|---|
| 12 张图加载数 | **1 / 12** | **12 / 12** |
| 链推进位置 | 停在第 2 张 | 走完全部 12 张 |

### 串行链 + 第 5 张首次返回 HTTP 500

| | 无插件 | 装插件 |
|---|---|---|
| 12 张图加载数 | 卡死 | **12 / 12** |
| 第 5 张请求次数 | 1 次（放弃） | **2 次（重试成功）** |
| 其余 11 张 | 1 次 | **1 次（无多余下载）** |

覆盖模式：原生 `loading=lazy` ｜ `data-src` ｜ 自研 IntersectionObserver ｜
`data-original` / `data-srcset` ｜ 滚动监听型 ｜ 延迟动态插入

| | 无插件 | 装插件 |
|---|---|---|
| 12 张图加载数 | **8 / 12** | **12 / 12** |

### 真实站点（reader.hipmh.top 第37话，86 张）

|---|---|---|
| 可见图片 | 20 秒只有 **1 张** | **11 秒 86/86** |

## 五、已知限制

- **不处理视频**（`<video>` 流式加载）
- **不处理 canvas / WebGL 渲染的内容**（如地图、某些网页游戏）
- **需要登录才能看的内容**不会因为插件而变得可见 —— 权限问题插件解决不了
- 极少数用「非标准私有协议」传输图片的站点（如 WebSocket 推流）不适用
- 对**无限滚动**的站点，会一次性加载更多内容，可能稍微多耗一点流量
- 需要 **Chrome / Edge 111+**

发现某个网站显示错乱？在插件弹窗里把「本站启用」关掉即可，不影响其他网站。

## 六、隐私

插件不收集、不上传任何数据。全部逻辑在本地浏览器内运行。
唯一的网络请求就是网页本来就要加载的那些图片。
